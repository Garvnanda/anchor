The commands below reproduce the OpenCode baseline. OpenClaw is the primary integration under evaluation. Its first milestone is a real tool call, a verified denial and a managed Qwen continuation. Both adapters will share the local runtime and portal.

Start the Python provider

From the repository root on Windows x64, use uv and Python 3.12.14. Setup installs pinned packages in a local environment and checks startup against the approved cached Qwen snapshot. The service runs inference in CPU FP32. The lock records the torch wheel tested on Windows. 

./option-a/python/setup-windows.ps1

The provider checks the SHA-256 of seven model and tokenizer files. The approved Qwen2.5-0.5B-Instruct snapshot revision is 7ae557604adf67be50417f59c2c2f167def9a775. Supply a local snapshot directory with --snapshot if your Hugging Face cache lives outside the default location. Missing files or mismatched hashes stop startup. The model weights live outside this repository. 

$env:ANCHOR_DETECTOR_TOKEN = [guid]::NewGuid().ToString('N')
./option-a/python/.venv/Scripts/python.exe option-a/python/serve.py --port 8081

Use Ctrl+C to stop. Supply the bearer token in the Authorization header. Accepted requests use the numeric loopback host and port. Browser-origin requests to the detector are rejected.

Verify model tool calling

The B1 smoke harness selects OpenCode 2.3.2, restricts the test session to two harmless color tools and checks the returned tool IDs. Its default Python is the original offline environment. You can point it to the new environment. 

$env:ANCHOR_PYTHON = (Resolve-Path option-a/python/.venv/Scripts/python.exe).Path
npm install --prefix option-a/.cache/b1 --no-audit --no-fund --save-exact @opencode/cli@2.3.2
node option-a/python/b1_smoke.mjs

The harness prints its evidence directory under the ignored local cache. A final detector-backed OFF/ON demonstration requires the C2 integration gate.

Build and open the portal

cd option-a/apps/dashboard
npm ci
npm test
npm run build

Serve the contents of dist/ from the same loopback origin as Person A’s portal API. Enter the portal bearer token to load history and connect to the event stream. The UI shows redacted events, decisions, provenance and independent sink receipts as supplied by the server. A disconnected stream displays a warning. An expired cursor triggers a new snapshot.

For local development run node build.mjs --fixtures, serve dist/ on loopback and open /?mode=fixture. This mode displays synthetic fixtures. The production build excludes the fixture file.

Local interfaces

The Python service exposes /health, /metadata, /v1/models, POST /v1/chat/completions and activation lookup. Health reports incompatible because the current probe failed live-format validation. Activation lookup returns an incompatible result with a null score for a recorded request and tool pair. Unknown pairs return HTTP 404. Use /api/health, /api/coverage, /api/runs, per-run event snapshots and /api/events/stream on the separate portal service. Exact fields and errors are in the versioned API reference.

Coverage and limitations

Person A’s A0 audit demonstrated pre-execution blocking for a controlled custom tool. Check the runtime coverage report for each tool and route. The TypeScript runtime owns policy decisions. The portal only displays evidence. Public SDK installation, CLI onboarding and live SSE acceptance depend on Person A’s packages and server.

The frozen detector caught 37 of 132 labeled injections and flagged 8 of 73 benign results in the observed OpenCode prompt format. The original MVP format yielded 127 detections and one benign flag on the same offline split. See docs/ml/parity-report.md for the methodology. Multiple tool results in one generation currently yield one aggregate activation measurement.
